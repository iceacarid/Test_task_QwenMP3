# Локальное веб-приложение: аудио → расшифровка → Qwen → DOCX

Веб-приложение, которое принимает аудиозапись рабочего совещания, распознаёт речь локально, обрабатывает расшифровку локальной моделью семейства Qwen и формирует структурированный протокол совещания в формате DOCX (дополнительно доступны TXT и PDF).

Все этапы работают полностью локально, без обращения к внешним LLM/ASR API. После установки моделей приложение работает без доступа в интернет.

## Архитектура

```
Аудио (MP3/WAV/M4A)
    │
    ▼
Whisper (faster-whisper, GPU)  →  текстовая расшифровка
    │
    ▼
Qwen (Ollama, GPU)  →  структурированный JSON (темы, решения, ответственные, сроки)
    │
    ▼
Генератор документа  →  DOCX / TXT / PDF
```

Whisper и Qwen на GPU не грузятся одновременно: модель распознавания загружается, обрабатывает файл и выгружается из VRAM, только потом запрос уходит в Qwen. Это позволяет уместить весь пайплайн в 8 Гб VRAM.

## Требования к оборудованию

**Минимальные:**
- CPU: 4 ядра
- RAM: 16 Гб
- GPU: не обязателен — без видеокарты всё работает на CPU (`int8`), но заметно медленнее (см. «Распределение GPU-памяти и работа без GPU»)
- Диск: ~15 Гб под образы Docker и модели

**Рекомендуемые (на чём разрабатывалось и тестировалось):**
- CPU: Intel i7-11700
- RAM: 64 Гб
- GPU: NVIDIA RTX 3050, 8 Гб VRAM
- Диск: SSD, 20+ Гб свободно (веса Qwen 7B ~4.7 Гб, Whisper large-v3 ~1.5 Гб, образы Docker ~15 Гб)

## Установка и запуск

### Требования к окружению
- Docker Desktop с включённым WSL2-бэкендом (Windows)
- Свежий NVIDIA-драйвер с поддержкой CUDA в WSL2 (для GPU-ускорения)
- Проверка перед запуском:
  ```powershell
  docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi
  ```
  Если видна информация о GPU — всё готово.

### Запуск
```bash
docker compose up --build -d
```

Первый запуск качает базовые образы и ставит зависимости (ffmpeg, LibreOffice) — занимает время. Веса Qwen нужно затянуть в контейнер `ollama` отдельно (они не входят в образ):

```bash
docker exec -it <имя-проекта>-ollama-1 ollama pull qwen2.5:7b-instruct
```

Точное имя контейнера — `docker ps`.

После этого открыть в браузере:
```
http://localhost:8000/
```

Модель Whisper (`large-v3`) скачивается автоматически при первой обработке аудио и кешируется в volume `whisper_cache` — второй запуск быстрее.

### Остановка
```bash
docker compose down
```
(volumes с моделями сохраняются, повторная закачка не требуется)

## Распределение GPU-памяти и работа без GPU

### Замеры (RTX 3050, 8 ГБ; ~1 ГБ занято системой в простое)

| Компонент | Занимает VRAM |
|---|---|
| Whisper `large-v3`, `int8_float16` | ~2.3 ГБ (пик 3.3 ГБ всего) |
| Qwen2.5-7B, `num_ctx=4096` | ~4.7 ГБ |
| Qwen2.5-7B, `num_ctx=8192` | ~5.0 ГБ |
| Qwen2.5-7B, `num_ctx=12288` | ~5.1 ГБ |
| Qwen2.5-7B, `num_ctx=16384` | ~5.3 ГБ |

Кэш контекста растёт примерно на 0.2 ГБ на каждые 4К токенов. Whisper + Qwen (8К) = ~7.3 ГБ + ~1 ГБ системе — вместе в 8 ГБ не помещаются, поэтому модели загружаются строго по очереди.

### Порядок загрузки и выгрузки моделей

1. Задача попадает в очередь GPU-задач (`GPU_WORKERS=1`): выполняется **одна** задача за раз, остальные ждут в статусе `queued` с `queue_position` (1 — следующая). Очередь ограничена `MAX_QUEUE` (20), сверх лимита `/process` отвечает `429`.
2. Перед распознаванием Qwen принудительно выгружается из Ollama (`keep_alive: 0`), чтобы память, оставшаяся от предыдущей задачи, не мешала Whisper.
3. Whisper загружается, распознаёт запись и выгружается.
4. Qwen загружается на время генерации (`keep_alive` = `LLM_KEEP_ALIVE`, 10 минут, чтобы не перезагружать модель между кусками длинной записи).
5. В конце задачи Qwen выгружается явно — следующая задача из очереди начинает с чистой VRAM.

В `docker-compose.yml` для Ollama заданы `OLLAMA_MAX_LOADED_MODELS=1` и `OLLAMA_NUM_PARALLEL=1`.

Проверено: три одновременные загрузки. Раньше одновременно шли три Whisper (пик VRAM 7.5 ГБ, +6.5 ГБ к базе), после завершения Qwen держал 5.8 ГБ. Теперь идёт одна задача, остальные `queued#1`, `queued#2`, порядок FIFO, после завершения VRAM возвращается к базовым ~1.2 ГБ. Цена — общее время (71 с против 55 с на трёх клипах по 90 с).

### Что происходит при нехватке VRAM

**Распознавание (Whisper)** — цепочка, каждое переключение пишется в лог и в поля задачи:

1. `cuda` + `int8_float16` (`device_mode: gpu`)
2. `cuda` + `int8` (`gpu_reduced`)
3. `cpu` + `int8`, та же модель `large-v3` (`cpu`)
4. `cpu` + `int8`, меньшая модель `ASR_CPU_FALLBACK_MODEL` (по умолчанию `medium`). Если запись длиннее `ASR_CPU_LARGE_MAX_MINUTES` (60 минут), на CPU сразу берётся меньшая модель.

Переход происходит только при ошибке нехватки памяти (`out of memory`, `bad_alloc`) или недоступности GPU (нет устройства, не найдены библиотеки CUDA). Прочие ошибки не скрываются. Если библиотеки CUDA недоступны, оставшиеся GPU-шаги пропускаются. Перед новой попыткой модель выгружается, а по `nvidia-smi` проверяется, что VRAM освободилась. Если GPU нет вообще, распознавание сразу идёт на CPU.

**Генерация (Qwen)** — при ошибке памяти в Ollama (`out of memory`, `requires more system memory`, падение runner-процесса) запрос повторяется в более лёгком режиме:

1. `gpu` — Ollama сама распределяет слои
2. `gpu_reduced` — `num_gpu=14` (часть слоёв на CPU), таймаут `LLM_TIMEOUT_REDUCED`
3. `cpu` — `num_gpu=0`, таймаут `LLM_TIMEOUT_CPU`

Режим запоминается до конца задачи. При перезапуске Ollama выполняется `LLM_CONN_RETRIES` повторов с паузой `LLM_RETRY_DELAY`.

В `/jobs/{id}` поле `device_mode` показывает режим отдельно для распознавания и генерации (`{"asr": "cpu", "llm": "gpu"}`), а `device_notes` — сообщения для пользователя, например «Недостаточно видеопамяти — распознавание переключено на CPU, обработка займёт больше времени».

> **Особенность Windows.** Драйвер NVIDIA на Windows по умолчанию (политика «CUDA Sysmem Fallback») при нехватке VRAM не возвращает ошибку, а незаметно использует системную память. В тестах на этой машине даже при занятых 7.9 из 8.2 ГБ Whisper и Ollama продолжали работать без ошибок (медленнее). Поэтому реальный OOM здесь не проявляется, а переключение на CPU надёжно срабатывает при отсутствии GPU или библиотек CUDA. Ветки OOM проверены имитацией сообщений об ошибках.

### Как запустить на CPU (без видеокарты)

```bash
docker compose -f docker-compose.yml -f docker-compose.cpu.yml up --build -d
```

Второй файл убирает резервирование GPU у контейнеров (`deploy: !reset {}`) и включает `ASR_DEVICE=cpu` и `LLM_FALLBACK_LADDER=cpu`. Ориентиры на i7-11700 (8 ядер): клип 90 с распознаётся на CPU за ~50 с, Qwen на CPU обрабатывает такой клип около минуты; для 30-минутной записи ожидайте ощутимо больше времени, чем на GPU.

## Выбор моделей

### Распознавание речи — faster-whisper (`large-v3`)
Выбран `faster-whisper` (CTranslate2-бэкенд для Whisper): даёт хорошее качество распознавания русской речи, работает быстрее оригинального `openai-whisper` за счёт квантования (`int8_float16`), укладывается в 8 Гб VRAM вместе с последующей работой Qwen. Как альтернативу рассматривался GigaAM (Sber, заточен специально под русскую речь) — не был протестирован в рамках задания по времени, оставлен как возможное направление доработки (см. "Дальнейшие улучшения").

### Языковая модель — Qwen2.5 (7B по умолчанию, 14B по выбору) через Ollama
Запускается локально через **Ollama** — самый простой и надёжный способ развернуть модель семейства Qwen без ручной настройки CUDA-окружения под инференс. Размер 7B в 4-битном квантовании (~4.5 Гб) полностью помещается в VRAM видеокарты 8 Гб, что даёт быструю генерацию без выгрузки слоёв на CPU.

**Выбор модели в интерфейсе.** Если в Ollama установлено несколько моделей `qwen*`, над кнопкой «Обработать» появляется список «Модель Qwen» (источник — `GET /models`, то есть `/api/tags` Ollama). Выбор запоминается в браузере и передаётся в поле `llm_model` запроса `/process`; неизвестная модель отклоняется с HTTP 400. Модель по умолчанию задаёт `QWEN_MODEL` в `docker-compose.yml`. Установить вторую модель:

```bash
docker compose exec ollama ollama pull qwen2.5:14b-instruct
```

**Сравнение 7B и 14B** (RTX 3050 8 ГБ, одни и те же записи, температура 0):

| | 7B (по умолчанию) | 14B |
|---|---|---|
| Размер в VRAM | ~5 ГБ, целиком на GPU | ~9 ГБ, около 41% слоёв уходит на CPU |
| Этап Qwen на клипе 90 с | ~24 с | ~63 с |
| Длинные записи (30 мин) | минуты | в 4–10 раз дольше |
| Качество | иногда общие формулировки итогов, редкие лишние решения (отсекаются фильтрами) | аккуратнее с именами и ответственными, но склонна превращать планы и пересказ в «решения» (исправлено определением решения в промпте и фильтром) |

Рекомендация: 7B на видеокарте 8 ГБ, 14B — если VRAM хватает для полной загрузки модели (16 ГБ и больше) или время обработки не важно.

## Как изменить промпт для Qwen

Системная инструкция вынесена в отдельный файл `prompts/protocol_system.txt` — не требует изменения кода приложения. Файл смонтирован в контейнер как volume, правки подхватываются сразу при следующем запросе, без пересборки Docker-образа.

Промпт задаёт:
- запрет на выдумывание фактов, ФИО, сроков, решений
- правило указывать ответственного/срок только если они прямо названы в записи
- требование помечать неясные фрагменты как `needs_review`, а не "исправлять по смыслу"
- определение решения: только явное согласие или поручение; мнения, пересказ чужих слов, планы и объявления компании решением не считаются; ответственный — человек или подразделение, а не роль («директор») и не организация
- формат ответа (строгий JSON-схема)

## Качество распознавания и протокола

### Распознавание (ASR)

Запись сначала проходит предобработку `ffmpeg`, затем распознаётся `faster-whisper` с защитой от типичных сбоев Whisper на реальных записях (музыка и тишина в начале, тихие и дальние спикеры, петли повторов).

| Этап | Что делает | Зачем |
|---|---|---|
| Предобработка ffmpeg | mono 16 кГц, `highpass=80 Гц`, `dynaudnorm` | тихие и дальние спикеры не теряются (без нормализации приветствие на 41–59 с записи пропадало целиком) |
| `vad_filter` (порог 0.35) | не отдаёт Whisper музыку и тишину | нет «Девушки отдыхают…» на вступительной музыке |
| `condition_on_previous_text=False` | не тянет прошлый текст в следующее окно | одна из причин петель повторов |
| `compression_ratio_threshold` 2.4, `log_prob_threshold` −1.0, `no_speech_threshold` 0.6, температуры `0.0,0.2,0.4,0.6`, `beam_size` 5 | переразбор сомнительных окон | галлюцинации и зацикливание |
| `hallucination_silence_threshold` 2.0 | отбрасывает текст, выданный в тишине | галлюцинации на паузах |
| Фильтр подписей | убирает «Играет музыка», «Субтитры…» и т. п. (`ASR_HALLUCINATION_PATTERN`) | подписи Whisper на музыке |
| `collapse_loops`, `dedupe_segments` | схлопывают зацикленные фразы и почти одинаковые соседние сегменты | 11 одинаковых сегментов подряд в исходной записи |

Автоматическая проверка на повторы — `repeats.repetition_report`: считает почти одинаковые соседние сегменты и максимальную частоту одной 6-граммы.

Результат на записи панельной дискуссии (29:44, средняя громкость −34 дБ, клиппинг 0 дБ, музыка в начале): дублей подряд было 11 — стало 0, максимум одной 6-граммы 11 — 1, приветствие 00:45–01:03 распознано, время ASR 252 с — 195 с.

### Протокол (Qwen)

- `num_ctx` считается по длине текста (в пределах `LLM_NUM_CTX_MAX`), ответ строго по JSON-схеме (структурированный вывод Ollama) — модель не может вернуть чужие ключи.
- Длинные записи режутся на куски с перекрытием (`LLM_CHUNK_CHARS`, `LLM_CHUNK_OVERLAP_CHARS`); пункты из кусков объединяются без дублей и сортируются по времени.
- Протокол считается **пустым**, если JSON не разобран, нет `agenda_items` или у всех пунктов пустой `topic_summary`. Тогда запускается повторный проход (до `LLM_MAX_ATTEMPTS`): более мелкие куски, уточнённый промпт `prompts/protocol_retry.txt`, температура выше на 0.15. Каждая попытка пишется в лог: токены, причина признания пустым, начало ответа.
- Если все попытки пустые — это не ошибка: пользователь получает сообщение и расшифровку (`.txt`), а не пустой DOCX. То же при слишком короткой записи или неразборчивой речи (одни повторяющиеся слоги): Qwen в этих случаях не вызывается.
- Защита от выдумок (`grounding.py`): ответственные, сроки, участники, докладчики и числа должны встречаться в расшифровке (с точностью до падежа); иначе значение убирается и отмечается в «Требует проверки». Срок вида `05:00` (модель путает его с таймкодом) убирается без пометки. Пометки `needs_review` без цитаты отбрасываются.
- Докладчики: диаризации (разделения по голосам) нет, поэтому имя докладчика Qwen угадывает по тексту. Ведущий обычно представляет участника или передаёт ему слово («перейти к Максиму», «Александр.»), и дальше говорит он, пока слово не передадут другому. Поэтому докладчик остаётся только если его имя звучало в форме обращения не раньше чем за `LLM_SPEAKER_MAX_AGE` секунд до начала пункта и после этого слово не передавали другому участнику; упоминание внутри речи («я знаю Максима 15 лет») слова не передаёт. Неподтверждённый докладчик заменяется на «докладчик не указан». Искажённые ASR варианты имён приводятся к полному имени из списка участников («Тарен» → «Карен Казарян», «Максим» → «Максим Бустовой»), если совпадение однозначное. Латинские записи в списке участников (DSL, ArenaData) в этой логике не учитываются.
- Отсев шума (`llm._clean`): пересказ без срока («сказал, что сделает») не считается решением; роли и служебные слова («участник», «докладчик») не попадают в участники и ответственные; в «Требует проверки» остаётся не больше двух содержательных пометок (имя, число, срок, ответственный, решение), общие фразы отбрасываются.
- Воспроизводимость: температура 0 и фиксированный `LLM_SEED` — одна запись даёт один и тот же протокол.
- Промпты не привязаны к типу записи: подходят и для совещания, и для конференции, лекции, интервью (если решений нет, выделяются обсуждавшиеся темы).

### Переменные окружения

Все пороги вынесены в окружение (значения по умолчанию в скобках).

**ASR:** `ASR_MODEL` (large-v3), `ASR_LANGUAGE` (ru), `ASR_BEAM_SIZE` (5), `ASR_TEMPERATURE` (0.0,0.2,0.4,0.6), `ASR_CONDITION_ON_PREVIOUS_TEXT` (0), `ASR_COMPRESSION_RATIO_THRESHOLD` (2.4), `ASR_LOG_PROB_THRESHOLD` (-1.0), `ASR_NO_SPEECH_THRESHOLD` (0.6), `ASR_VAD_FILTER` (1), `ASR_VAD_THRESHOLD` (0.35), `ASR_VAD_MIN_SILENCE_MS` (500), `ASR_VAD_SPEECH_PAD_MS` (400), `ASR_HALLUCINATION_SILENCE_THRESHOLD` (2.0), `ASR_AUDIO_FILTERS` (highpass=f=80,dynaudnorm=f=100:g=31:p=0.95:m=30), `ASR_PREPROCESS` (1), `ASR_DEDUPE_SIMILARITY` (0.9), `ASR_DEVICE` (auto, cuda или cpu), `ASR_CUDA_COMPUTE_TYPES` (int8_float16,int8), `ASR_CPU_COMPUTE_TYPE` (int8), `ASR_CPU_FALLBACK_MODEL` (medium; пусто — отключить), `ASR_CPU_LARGE_MAX_MINUTES` (60), `ASR_MAX_AUDIO_MINUTES` (240), `ASR_FFMPEG_TIMEOUT` (3600).

**Qwen:** `QWEN_MODEL`, `OLLAMA_URL`, `LLM_TEMPERATURE` (0: детерминированная генерация, один и тот же файл даёт один и тот же протокол; повторные проходы при пустом результате повышают её на 0.15 за попытку), `LLM_SEED` (42), `LLM_NUM_CTX_MAX` (12288), `LLM_RESERVE_OUT_TOKENS` (2048), `LLM_CHUNK_CHARS` (9000), `LLM_CHUNK_OVERLAP_CHARS` (1500), `LLM_MAX_ATTEMPTS` (3), `LLM_TIMEOUT` (900), `LLM_MIN_TRANSCRIPT_CHARS` (200), `LLM_MIN_DIVERSITY` (0.15), `LLM_USE_SCHEMA` (1), `LLM_KEEP_ALIVE` (10m), `LLM_FALLBACK_LADDER` (gpu,gpu_reduced,cpu), `LLM_GPU_LAYERS_REDUCED` (14), `LLM_TIMEOUT_REDUCED` (1800), `LLM_TIMEOUT_CPU` (3600), `LLM_CONN_RETRIES` (2), `LLM_RETRY_DELAY` (5), `LLM_MAX_OUTPUT_TOKENS` (3072, предел длины ответа Qwen), `LLM_SPEAKER_MAX_AGE` (600 секунд; 0 — не проверять докладчиков).

**Приложение:** `GPU_WORKERS` (1), `MAX_QUEUE` (20), `MAX_UPLOAD_MB` (500).

**Формат DOCX.** Документ собирается из `templates/protocol_template.docx` (шапка, заголовки разделов, таблицы подписей и стили берутся из шаблона; абзацы докладчика, итога и решения копируются с его форматированием). Если шаблон недоступен, используется запасной генератор. Строка «Решение не принято» показывается только при двух и более решениях в протоколе; без решений выводится «Решения и поручения в записи не зафиксированы».

## Ограничения реализованного решения

- **Без диаризации спикеров.** Имена участников извлекаются только если они реально прозвучали в речи (кто-то назвал их вслух). Ведущий совещания, если его никто не назвал по имени, не попадёт в список участников — это соответствует требованию "не придумывать отсутствующие факты", а не ошибка.
- Whisper (`large-v3`) и Qwen (`7B`) не работают на GPU одновременно, а задачи выполняются по одной (очередь `GPU_WORKERS=1`) — это надёжно на 8 ГБ VRAM, но общее время больше, чем в параллельной схеме на более мощном железе.
- Очередь и статусы задач хранятся в памяти процесса: после перезапуска бэкенда ожидающие задачи теряются (интерфейс сообщает «Задача не найдена»).
- PDF-экспорт зависит от LibreOffice headless-конвертации — на очень длинных документах возможна задержка в несколько секунд.
- **Качество ASR зависит от записи.** Проверено на искусственных искажениях: тихий дальний спикер (−26 дБ, чередование с ближним) — распознаётся около 55–60% текста; фон с отношением сигнал/шум около −12 дБ — около 50%; запись 8 кГц — около 45%. Фильтры настраиваются через `ASR_AUDIO_FILTERS`; шумоподавление (`afftdn`) в тестах ухудшало результат и по умолчанию выключено.
- **Проверка на галлюцинации лексическая:** она ловит выдуманные имена, сроки и числа, но не смысловые ошибки. Пример: модель может приписать докладчику компанию, о которой тот лишь говорил, или записать клиента в участники. Определение докладчика без диаризации приблизительное.
- Модель 7B иногда путает срок исполнения с таймкодом (`05:00`); такой срок убирается, текст решения остаётся.
- **Windows и нехватка VRAM.** Драйвер NVIDIA по умолчанию (политика «CUDA Sysmem Fallback») при нехватке видеопамяти не возвращает ошибку, а использует системную память, работая медленнее. Поэтому настоящий OOM на такой машине не проявляется; ветки fallback проверены имитацией ошибок и реальными отказами GPU (нет устройства, нет библиотек CUDA).
- **Видеопамять и посторонние программы.** Если браузер, Docker Desktop и другие программы занимают 2–3 ГБ VRAM, Qwen (5 ГБ) упирается в предел, и драйвер Windows не выдаёт ошибку, а замедляет генерацию до десятых долей токена в секунду (наблюдалось: 24 → 0.06 токена/с). Такой запрос удерживает очередь до таймаута (`LLM_TIMEOUT`, 900 с). Ответ ограничен `LLM_MAX_OUTPUT_TOKENS`; при заметной нагрузке на GPU закройте лишние программы или уменьшите `LLM_NUM_CTX_MAX`.
- Нативные зависания CTranslate2 исключением не перехватить; защита от них — только пропуск GPU-шагов при недоступном CUDA-рантайме.
- Результаты обработки сохраняются в `data/` и автоматически не удаляются (аудио после обработки удаляется). Для конфиденциальных записей настройте периодическую очистку каталога. Лимит размера (`MAX_UPLOAD_MB`) проверяется после получения файла; для ограничения самой передачи ставьте перед приложением обратный прокси.
- Тестовая аудиозапись совещания синтезирована через TTS (ElevenLabs Studio) по сценарию диалога. Дополнительно система проверена на публичных записях с YouTube: панельная дискуссия (около 30 минут, музыка в начале, тихий звук), собеседование на должность PM (m4a), пресс-конференция хоккейного клуба. На них видны слабые места: искажённые ASR имена собственных, названия компаний в списке участников, докладчик чаще «не указан». Реальные конфиденциальные записи в проверках не использовались.
- Приложение рассчитано на локальную работу в доверенной сети: авторизации и HTTPS нет, наружу порт 8000 открывать не следует.

## Дополнительные возможности

Реализовано:
- Выбор формата выгрузки: DOCX (по умолчанию, обязательный формат) / TXT / PDF
- Обработка ошибок формата файла и неудачного распознавания
- Таймкоды — каждому вопросу протокола проставляется метка `[ММ:СС]` момента начала обсуждения в записи (в самом документе, не в интерфейсе)
- Отображение прогресса обработки — этапы «Очередь → Расшифровка → Qwen (с номером попытки) → Готово», позиция в очереди, сообщения о переключении на CPU; обработка асинхронная, задача восстанавливается после перезагрузки страницы
- Очередь GPU-задач: одновременные загрузки выстраиваются по порядку (`queued` с позицией)
- Автоматический повторный проход Qwen при пустом протоколе и выдача расшифровки, если протокол составить не удалось
- Автоматический переход на CPU при нехватке видеопамяти или отсутствии GPU
- Выбор модели Qwen (7B/14B) в интерфейсе, модель на каждую запись
- Просмотр расшифровки — доступна сразу после этапа распознавания, до готовности итогового протокола (кнопка "Показать расшифровку")

Не реализовано в рамках текущей версии (возможные направления доработки):
- Диаризация спикеров
- Редактирование результата перед скачиванием
- История обработанных записей
- Сравнение с GigaAM как альтернативной ASR-моделью

## Что изменить для использования в рабочей среде предприятия

- Персистентная очередь задач (Celery/RQ или Redis) вместо очереди в памяти процесса — критично при нескольких пользователях и перезапусках.
- Персистентное хранилище истории и статусов (сейчас данные только на файловой системе, без БД).
- Диаризация спикеров (`pyannote.audio`) для корректного различения участников без ASR-транскрипции их имён.
- Логирование и мониторинг (сейчас минимальные логи uvicorn).
- Аутентификация — сейчас приложение открыто без авторизации, для внутреннего инструмента компании нужна как минимум базовая защита доступа.
- Тестирование на более широком наборе реальных записей с разным качеством звука/акцентами для калибровки промпта.
- Выбор ASR-модели в интерфейсе (выбор модели Qwen уже реализован).

    txt_builder.py         — генератор TXT

scripts/
