# Локальное веб-приложение: аудио → расшифровка → Qwen → DOCX

Веб-приложение, которое принимает аудиозапись рабочего совещания, распознаёт речь локально, обрабатывает расшифровку локальной моделью семейства Qwen и формирует структурированный протокол совещания в формате DOCX (дополнительно доступны TXT и PDF).

Все этапы работают полностью локально, без обращения к внешним LLM/ASR API. После установки моделей приложение работает без доступа в интернет.

## Архитектура

```
Аудио (MP3/WAV/M4A)
    │
    ▼
Whisper (faster-whisper, GPU)  →  текстовая расшифровка
    │
    ▼
Qwen (Ollama, GPU)  →  структурированный JSON (темы, решения, ответственные, сроки)
    │
    ▼
Генератор документа  →  DOCX / TXT / PDF
```

Whisper и Qwen на GPU не грузятся одновременно: модель распознавания загружается, обрабатывает файл и выгружается из VRAM, только потом запрос уходит в Qwen. Это позволяет уместить весь пайплайн в 8 Гб VRAM.

## Требования к оборудованию

**Минимальные:**
- CPU: 4 ядра
- RAM: 16 Гб
- GPU: не обязателен (Whisper и Qwen могут работать на CPU через `int8`-квантование, значительно медленнее)
- Диск: ~15 Гб под образы Docker и модели

**Рекомендуемые (на чём разрабатывалось и тестировалось):**
- CPU: Intel i7-11700
- RAM: 64 Гб
- GPU: NVIDIA RTX 3050, 8 Гб VRAM
- Диск: SSD, 20+ Гб свободно (веса Qwen 7B ~4.7 Гб, Whisper large-v3 ~1.5 Гб, образы Docker ~15 Гб)

## Установка и запуск

### Требования к окружению
- Docker Desktop с включённым WSL2-бэкендом (Windows)
- Свежий NVIDIA-драйвер с поддержкой CUDA в WSL2 (для GPU-ускорения)
- Проверка перед запуском:
  ```powershell
  docker run --rm --gpus all nvidia/cuda:12.2.0-base-ubuntu22.04 nvidia-smi
  ```
  Если видна информация о GPU — всё готово.

### Запуск
```bash
docker compose up --build -d
```

Первый запуск качает базовые образы и ставит зависимости (ffmpeg, LibreOffice) — занимает время. Веса Qwen нужно затянуть в контейнер `ollama` отдельно (они не входят в образ):

```bash
docker exec -it <имя-проекта>-ollama-1 ollama pull qwen2.5:7b-instruct
```

Точное имя контейнера — `docker ps`.

После этого открыть в браузере:
```
http://localhost:8000/
```

Модель Whisper (`large-v3`) скачивается автоматически при первой обработке аудио и кешируется в volume `whisper_cache` — второй запуск быстрее.

### Остановка
```bash
docker compose down
```
(volumes с моделями сохраняются, повторная закачка не требуется)

## Выбор моделей

### Распознавание речи — faster-whisper (`large-v3`)
Выбран `faster-whisper` (CTranslate2-бэкенд для Whisper): даёт хорошее качество распознавания русской речи, работает быстрее оригинального `openai-whisper` за счёт квантования (`int8_float16`), укладывается в 8 Гб VRAM вместе с последующей работой Qwen. Как альтернативу рассматривался GigaAM (Sber, заточен специально под русскую речь) — не был протестирован в рамках задания по времени, оставлен как возможное направление доработки (см. "Дальнейшие улучшения").

### Языковая модель — Qwen2.5-7B-Instruct через Ollama
Запускается локально через **Ollama** — самый простой и надёжный способ развернуть модель семейства Qwen без ручной настройки CUDA-окружения под инференс. Размер 7B в 4-битном квантовании (~4.5 Гб) полностью помещается в VRAM видеокарты 8 Гб, что даёт быструю генерацию без выгрузки слоёв на CPU.

Модель настраивается через переменную окружения `QWEN_MODEL` в `docker-compose.yml` — при наличии более мощного GPU можно перейти на Qwen2.5-14B-Instruct для более точного структурирования (ценой скорости).

## Как изменить промпт для Qwen

Системная инструкция вынесена в отдельный файл `prompts/protocol_system.txt` — не требует изменения кода приложения. Файл смонтирован в контейнер как volume, правки подхватываются сразу при следующем запросе, без пересборки Docker-образа.

Промпт задаёт:
- запрет на выдумывание фактов, ФИО, сроков, решений
- правило указывать ответственного/срок только если они прямо названы в записи
- требование помечать неясные фрагменты как `needs_review`, а не "исправлять по смыслу"
- формат ответа (строгий JSON-схема)

## Ограничения реализованного решения

- **Без диаризации спикеров.** Имена участников извлекаются только если они реально прозвучали в речи (кто-то назвал их вслух). Ведущий совещания, если его никто не назвал по имени, не попадёт в список участников — это соответствует требованию "не придумывать отсутствующие факты", а не ошибка.
- Whisper (`large-v3`) и Qwen (`7B`) не работают на GPU одновременно — обработка идёт последовательно, что увеличивает общее время по сравнению с параллельной схемой на более мощном железе.
- Обработка синхронная, без очереди задач — одновременная загрузка нескольких файлов не поддержана (см. "Дальнейшие улучшения").
- PDF-экспорт зависит от LibreOffice headless-конвертации — на очень длинных документах возможна задержка в несколько секунд.
- Тестовая аудиозапись синтезирована через TTS (ElevenLabs Studio) по заранее написанному сценарию диалога — реальная встреча с живыми участниками не записывалась по соображениям приватности. Из-за синтетической озвучки речь звучит чище живой (меньше запинок/перебиваний), чем в реальном совещании.

## Дополнительные возможности

Реализовано:
- Выбор формата выгрузки: DOCX (по умолчанию, обязательный формат) / TXT / PDF
- Обработка ошибок формата файла и неудачного распознавания
- Таймкоды — каждому вопросу протокола проставляется метка `[ММ:СС]` момента начала обсуждения в записи (в самом документе, не в интерфейсе)
- Отображение прогресса обработки — этапы "Распознавание → Qwen → Готово" с индикатором, обработка асинхронная (job-based, фронт опрашивает статус)
- Просмотр расшифровки — доступна сразу после этапа распознавания, до готовности итогового протокола (кнопка "Показать расшифровку")

Не реализовано в рамках текущей версии (возможные направления доработки):
- Диаризация спикеров
- Редактирование результата перед скачиванием
- Очередь задач при загрузке нескольких файлов (сейчас один файл обрабатывается за раз, параллельные запросы не выстраиваются в очередь)
- История обработанных записей
- Сравнение с GigaAM как альтернативной ASR-моделью

## Что изменить для использования в рабочей среде предприятия

- Асинхронная очередь задач (Celery/RQ или встроенный `asyncio`-воркер) вместо синхронной обработки одного файла за раз — критично при нескольких пользователях.
- Персистентное хранилище истории и статусов (сейчас данные только на файловой системе, без БД).
- Диаризация спикеров (`pyannote.audio`) для корректного различения участников без ASR-транскрипции их имён.
- Логирование и мониторинг (сейчас минимальные логи uvicorn).
- Аутентификация — сейчас приложение открыто без авторизации, для внутреннего инструмента компании нужна как минимум базовая защита доступа.
- Тестирование на более широком наборе реальных записей с разным качеством звука/акцентами для калибровки промпта.
- Возможность выбора между несколькими ASR/LLM моделями через интерфейс (архитектурно уже подготовлено — модели настраиваются конфигом/переменными окружения).

## Структура репозитория

```
backend/
  Dockerfile
  entrypoint.sh          — настройка CUDA-библиотек и запуск сервера
  requirements.txt
  app/
    main.py              — FastAPI, эндпоинт /process
    asr.py                — распознавание речи (faster-whisper), таймкоды
    jobs.py                — хранилище статусов фоновых задач (для прогресс-бара)
    llm.py                — обработка Qwen через Ollama API
    docx_builder.py       — генератор DOCX
    txt_builder.py         — генератор TXT
    pdf_builder.py         — конвертация в PDF через LibreOffice
frontend/
  index.html, style.css, script.js  — веб-интерфейс
prompts/
  protocol_system.txt    — системный промпт для Qwen (редактируется отдельно от кода)
templates/
  protocol_template.docx — образец структуры протокола (ориентир для docx_builder.py)
scripts/
  dialogue_script.txt    — сценарий тестовой аудиозаписи
docker-compose.yml
data/                     — результаты обработки (volume)
```
